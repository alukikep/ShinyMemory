# 工作完整生命周期

> 正式内容：job.studio_shoot（摄影棚拍摄，带表现检定）。工作面板与重点偶像见「接取」一节。

## 当前状态

已实现轻量生命周期：

```text
事务所邀约
→ 工作上限 / canReplaceDay
→ JobAssignment + scheduleOverrides
→ 工作当天到点自动完成
→ 玩家到场可参与并领奖
→ 次日清理日程覆盖
```

明确不做的：

- 未参与日志；
- 失败/缺席状态；
- 工作历史页面；
- 工作执行后的额外事件。

## 设计原则

```text
工作当天，偶像一定会完成工作。
玩家参与 = 多一个获得奖励的机会。
玩家不参与 = 没有奖励，也没有惩罚。
```

关键词：

- **自动完成**：不依赖玩家；
- **可选参与**：玩家到场才有额外收益；
- **无缺席惩罚**：不扣钱、不扣压力、不降好感、不标记失败；
- **不增加负担**：不写未参与日志，不保留待办列表；
- **不重复结算**：参与后工作实例直接移除。

## 数据结构

`JobDef`：

```ts
type JobDef = {
  id: string;
  name: string;
  locationId: string;
  fromMinute: number;
  toMinute: number;
  pay: number;
  label?: string;
  /** 接取后至少提前几天才能排到工作；缺省 1（明天）。 */
  leadDays?: number;
  /** 完成后冷却天数。 */
  cooldownDays?: number;
  effects?: Effect[];
};
```

工作实例：

```ts
type JobAssignment = {
  id: string;
  jobId: string;
  idolId: string;
  day: number;
  fromMinute: number;
  toMinute: number;
  locationId: string;
};
```

`GameState.jobs: JobAssignment[]` 只保存尚未完成的工作。

没有 `completed` 状态，也没有历史数组：

```text
完成 → 从 jobs 移除
```

工作上限：

```text
初始 1 份
工作区 Lv1 / Lv2 / Lv3 → 2 / 3 / 4 份
```

上限统计的是 `state.jobs.length`，也就是**所有偶像、所有日期**的未完成工作总数。
完成或取消一份工作后，名额立即释放。

日程覆盖仍在当天保留，次日由 `pruneScheduleOverrides` 清理。

## 接取

地点页**不再**为每份工作铺一个按钮。事务所只留一个入口：

```text
查看可以接的工作  →  工作面板（JOBS）
```

面板列出今日抽中的工作，已排工作在上方独立展示；每条邀约给出：

| 字段 | 说明 |
|---|---|
| 名称 / 报酬 / 地点 / 时段 | 基本盘 |
| 检定要求 | 例如「需要表现 E」，按**每个偶像各自的等级**算成功率 |
| 派谁去 | 每个已出道偶像一个按钮，写明最早可排的日期与她的成功率 |
| 日期 | 自动选择最早可排日期；不额外弹日期选择，减少操作 |
| 占用 | 已排工作显示「占用至 X 月 X 日」，让玩家看到哪个名额会被锁到什么时候 |
| 未解锁 | `requires` 不满足时显示「未解锁」（不写条件） |
| 隐藏 | `hiddenUntilUnlocked: true` 且未解锁时，整条从面板消失（剧情解锁用） |

解锁条件可以是属性、粉丝、或剧情 flag：

```jsonc
{ "requires": [{ "kind": "flag", "key": "unlocked.magazine_cover" }],
  "hiddenUntilUnlocked": true }
```

判定用 `checkCondition`（不是展示文案）——曾经用 `describeCondition` 判过，
flag 没有文案时会被当成已满足，工作直接可接。`content:audit` 的
`job-unlock-flag` 规则会挡住"引用了没人设置的 flag"。

偶像侧的变化：

- 接工作默认派给**重点偶像**（`focusIdolId`，名册里可切换、写进存档）；
- 面板里也可以直接点别的偶像派去（`acceptJob(..., idolId)`）；
- 同一天可以让两个偶像各接一份工作——前提是工作区已升到 2 席；`JobAssignment` 本来就带 `idolId`，`canReplaceDay` 也是按单个偶像判断的。

`acceptJob` 的校验：

1. 校验事务所、目标偶像**已出道**、未来日期；
2. 日期必须 ≥ `currentDay + max(1, job.leadDays ?? 1)`；
3. `state.jobs.length` 是否已到工作上限（见下节）；
4. 同一偶像同一工作已有未完成实例 → 拒绝；
5. `canReplaceDay` 校验档期；
6. 创建 `JobAssignment`；
7. 写入 `ActorState.scheduleOverrides`，`mode: 'replace-day'`；
8. 写一条“接下了”日志。

## 每日邀约与主动刷新

- 工作池仍来自当前内容包；新游戏及跨游戏日生成最多 5 份、不重复的邀约，数量不足时按实际数量展示。
- 抽取排除冷却未完成、已被占用、剧情尚未解锁的工作。普通属性、总粉丝与档期门槛保留展示，抽中不等于当前就能接取。
- 当日列表稳定，不随重点偶像、面板开关或无关行动的随机数变化；独立随机序列按存档 seed 和游戏日抽样，不消耗剧情/检定 RNG。
- 在事务所安排阶段，每游戏日可免费主动刷新一次，不耗时；优先换入未展示候选，不足时保留部分旧邀约。无可替换候选则禁用，不消耗次数。
- 主动刷新只替换邀约，不修改已排工作及偶像日程。接取不自动补位；未刷新时取消可恢复原邀约，已被主动刷新移出的工作取消后不自动加入。
- 当天新解锁的剧情工作进入候选池，可经主动刷新或次日抽取出现，不强行插入当前列表。
- 接取命令同时验证当日邀约、完整 requires、冷却、占用、档期和工作上限；界面隐藏不能替代命令校验。
- `GameState.jobInvitations` 保存 `{ day, jobIds, refreshed }`；存档版本 20，从 19 迁移时初始化当日邀约，不清除已有工作与进度、不更改内容纪元。普通重载保持刷新状态，回退旧存档仍会回退状态。

实现：`src/core/jobInvitations.ts` 负责候选、每日快照与刷新；`sim.ts` 接入新游戏、跨天、打开面板及接取命令，`scene.ts` 只做纯投影。旧状态或调试跳天尚未写入快照时，先按当前游戏日确定性派生，打开面板时保存；不得在渲染时修改状态。

回归：`jobInvitations.test.ts` 覆盖去重、冷却边界、剧情隐藏、每日限次、无替换不扣次数、命令门槛、取消、跨天和迁移；`tests/prologue/jobInvitations.spec.ts` 覆盖刷新按钮、读档与次日重置。

## 工作上限与取消

### 同时负责上限

- 初始 **1 份**，所有日期、所有偶像共用；
- 工作区升级 **¥5,000 / ¥15,000 / ¥30,000**，对应 **2 / 3 / 4 份**；
- 上限在 `acceptJob` 命令层检查，界面只负责显示和禁用；
- `buildJobBoard` 返回 `slots: { used, cap, full }`，工作板显示“已排工作 N/M”。

### 日期与占用

- `jobDatesFor` 返回未来 7 天的候选日期；工作板自动取**最早可用日**。
- 不额外弹日期选择；玩家只需要选“派谁去”。
- `JobDef.leadDays` 是**前置期**：例如 `leadDays: 7` 时，接取后最早第 7 天才能排到。
- 从接取到工作完成，这份工作一直占一个名额；大工作需要 7 天前置期，就相当于锁住一个名额 7 天。
- `JobDef.cooldownDays` 是完成后的冷却，和前置期分开计算。
- 工作板的活动列表显示「占用至 X 月 X 日」。
- **首次接取不受冷却影响**：只有 `jobCooldowns` 有记录（即完成过）时才应用冷却。大工作的长冷却不会在开局把工作锁住。

### 取消

取消是“排期阶段的撤销”，不是完成工作：

```text
只允许：工作还没开场（now < day + fromMinute）
不允许：已经开场 / 已经结算
代价：不退钱、不耗时间、不写冷却
```

`cancelJob` 必须同时删两处：

```text
state.jobs 里的 JobAssignment
actor.scheduleOverrides 里同 id 的 replace-day 覆盖
```

只删第一处会出现“名额空了，但日程表还占着那一天”；只删第二处会出现“日程空了，但工作还会结算”。

日程表不需要恢复备份：覆盖被删后，`getSchedulesForDay` 会重新从 `actor.schedule` 生成当天模板。

工作当天：

```text
10:00–16:00 录音棚 · 杂志拍摄
```

日程表显示临时工作，名册显示录音棚。

## 自动完成

`advanceTime`、读档、调试跳天都会调用：

```ts
completeDueJobs(state)
```

工作到点而玩家没到场 → **按 20% 结算**，并照常掷检定（失败再乘 failurePayRatio）。
属性成长降一档（tier 10 → 5、5 → 3、3 → 1），**粉丝归零**——她确实去上班了，只是没有制作人在旁边推。

冷却从**完成那天**开始算：`jobCooldowns[jobId] = 完成日`，再按 `cooldownDays` 锁定若干天。
一份工作同时只能派一个人（被派出期间全城锁死）。

当前时间达到或超过工作结束时间：

```text
从 GameState.jobs 移除
```

行为：

- 不扣钱；
- 不扣体力；
- 不涨压力；
- 不降好感；
- 不写日志；
- 不标记失败；
- 不生成历史记录。

玩家完全不管工作，工作也会“完成”，只是没有任何结算。

## 玩家参与

条件：

```text
工作当天
+ 工作地点
+ 工作时段内
+ state.jobs 中存在该工作
+ 该工作的偶像已出道
```

工作地点行动区出现：

```text
参与：杂志拍摄
10:00–16:00 · ¥1,200
```

参与后走**结果页**（和行动一致，不是把一句日志丢回安排页）：

1. 有 `check` 时先掷骰；
2. 成功拿全额，失败按 `failurePayRatio`（默认 0.5）结算；
3. 应用 `effects` 或 `failureEffects`；
4. 时间推进到工作结束，从 `jobs` 移除；
5. `phase = 'activityResult'`，结果文本取自 `resultTexts` / `failureTexts`（缺省退回 `description`），后面接「收入 ¥xxx」。写一条日志。

日程覆盖仍保留到当天结束。

## 无惩罚

未参与不会改变任何数值。

没有：

```text
工作失败
缺席
她对你失望
```

因此工作只是“当天多了一个可参与的机会”。

## 日程表与名册

工作日：

```text
4月12日 星期日
10:00–16:00 录音棚 · 杂志拍摄
临时
```

名册：

```text
现在：录音棚
```

完成后当天仍显示工作；次日恢复默认安排。

## 防重复

- 同一偶像同一工作未完成时，不再出现在邀约；
- 同一自由日只能被一个工作占用；
- 参与后立即从 `jobs` 移除；
- 工作完成后不会再次出现。

## 当前边界

未实现：

- 工作当天额外事件；
- 工作失败/成功判定；
- 工作报酬浮动；

- 多日工作；
- 工作地点外的远程参与。

- 取消释放名额、删除覆盖、恢复周日程；
- 开场后取消被拒绝；
- 同一工作不重复邀约；
- 工作到点自动移除；
- 自动完成不发奖励、不写日志；
- 玩家参与发钱/EXP；
- 参与推进到工作结束；
- 参与后工作移除；
- 日程表显示临时工作；
