# 偶像内容档案实施计划

> 2026-11-04 · 只读 CLI、审查台内容档案及关联事实共用已实现；覆盖率口径迁移记录见 [B2](architecture-improvement-plan.md#b2-实施结果2026-11-04)。

## 1. 第一版目标

开写一个偶像前，只查一个入口即可知道：已有几张卡、多少章、几条招募/长线、多少专属行动/话题/事件；具体是什么；哪些待审、哪些尚未接入。统计自动读取内容源，人只记录后续生产计划，不手工维护数量。

提供只读命令、JSON 输出及审查台页面。运行 `npm run review`，点击顶栏「内容档案」，选择偶像、范围和内容类型，展开条目查看版本、文件与原文出处；审批或修改后点击「刷新档案」。返回队列保留当前审查状态。请求失败显示原因并支持重试，不把失败当作零内容。

页面通过只读 `GET /api/review/inventory` 与 CLI 共用 `tools/contentInventoryService.ts` 的读取和统计服务；报告契约位于 `src/shared/contentInventoryTypes.ts`。需要本地审查开发服务器。它不新增玩家页面、不自动审批、不改生成物、不调整游戏运行逻辑。

查询接口：

```bash
npm run content:inventory                       # 全角色简表
npm run content:inventory -- --idol mano        # 单角色分类汇总
npm run content:inventory -- --idol mano --details
npm run content:inventory -- --idol mano --json # 供后续界面/模型使用
```

需要重定向为纯 JSON 时使用 `npm run --silent content:inventory -- --idol mano --json`，避免 npm 自己打印命令头。`--details` 展开条目，`--json` 输出完整结构；同时指定时以 JSON 为准。警告不阻断只读查询；读盘失败、非法文件/参数或未知偶像非零退出。

简表的卡为「完整接入/登记」，章为「链已接入/对话可用/原卡总章数」。缺一个对话时整链尚未装配，已批准的其他对话仍可用，因此后两列可能不同。其余产量仅计已接入条目，待审与待修改按内容键合并为待处理任务。单偶像查询保留全局通用与待确认清单，避免隐去未能分配的内容。

简表只输出计数、警告数；明细输出名称、内容 id、源文件、版本、归属依据、审批与接入状态、已有原文出处。未知偶像或非法参数必须非零退出并说明原因。排序稳定，JSON 不混入展示日志。

## 2. 数据来源与可信边界

| 来源 | 用途 |
|---|---|
| BASE_PACK + approved 文件，经现有合并与 attachPendingChapters 拼装 | 当前源文件可装配出的正式内容，不另写一套装配规则 |
| content-review/drafts、revisions | 待审稿与修改稿，按目录确定流程状态 |
| PENDING_CHAPTERS + CHAPTER_SOURCES | 章节所属链、卡名、章节编号、原文编号及未接入结构 |
| 正式角色、话题与动作/事件的显式字段 | 按角色归属与引用关系查询 |
| approved.generated.ts | 仅比较生成快照是否落后，不代替 approved 源文件当唯一事实来源 |

工具不能证明最近一次 dist 构建包含这些内容。展示用语采用「已接入（源包）」，并注明是源码装配结果；不得把它写成「已部署」「当前玩家已可触发」。生成快照不同步时报告警告，工具不自行运行 sync。

复用前核对装配、文件读取与版本处理接口；有必要时提取小范围公共函数，保留原工具行为。读取失败、重复 id、无法识别归属要显式报告，不当作 0 或静默跳过。

## 3. 数量与归属口径

- 卡面：用卡面出处登记与链步骤的映射识别，不仅凭 kind='card' 或 id 命名推断。一张卡计一次，章节单列；部分接入显示如 3/5，不把每段对话算成一张卡。
- 招募与长线：有步骤明确 `complete.status='recruited'` 才归招募；其余显式 arc 且非豁免链归长线。豁免本身不等于招募，未能分类的链单列警告。
- 行动：单一 idolIds 为专属，多 idolIds 为多人关联；无 idolIds 的训练等记为通用，不加入每个人的专属数量。全部行动与其中的互动行动可分别列出，不只统计 kind='bond'。
- 话题：按宿主角色/显式目标归属，不依赖 '<idol>.chat.' 前缀作为唯一标准。
- 对话：区分主归属和参与（例如 idolId、角色 speaker/cast）；同一对话可关联多人，但全局唯一条目不重复计数。剧本行数、节点数不等于对话篇数。
- 事件：显式 afterIdol、固定 cast、角色条件等关联须保留字段路径及关联含义；参与、条件引用和专属分别标明。单凭 arrival 入口、地点、名称/正文提及或 id 前缀不能算某偶像专属事件。动态组合无法确定参与者时标为通用/动态。
- 共享工作、物品和商店另列关联与用途，不把全员可用内容重复加进各偶像专属产量。
- 「专属」「多人参与」「条件关联」「通用」「待确认」是不同关系；一条内容若同时有多个依据，按内容键去重并保留全部依据。各分类数字不能直接相加作为作品总量。

旧 content:coverage 曾将所有到达事件计入每个人事件数量；B2 已先核对全部真实名单，再改用共用关联事实。数值门槛未变；`content:coverage:compare` 保留旧、新名单及依据对比。当前数据无差异，边界误计用固定样例拦截。

## 4. 审批、接入与修订

审批与接入用两个维度表示：

- 审批：待审 / 待修改 / 已批准；基础 TS 结构标为「结构内容，不走条目审批」。
- 接入：已接入源包 / 未接入（附原因，如缺对话、结构未挂载）/ 不适用。

内容唯一键使用 kind + payload.id；**话题例外：`topic:actorId/id`**，与装配器按宿主查重一致，两个 NPC 的 greeting 不算重复。草稿 id、rootId、version、supersedes 用于追踪版本。上线旧版与待审修订同时展示；旧版仍计一次已接入内容，修订计一次待处理任务，不把它当两份作品。修订变更归属时保留旧版产量，并把待处理任务列给新归属。废弃、归档仅列文件数，不进入当前产量。

没有显式角色归属的待审稿可沿已登记链/宿主关系定位；仍无法关联时进入「待确认归属」清单，并给出文件位置。不能宣称角色列表已经覆盖所有这类草稿。

## 5. 分阶段实现

1. **统计内核与固定样例（已实现）**：[contentInventory.ts](../../src/core/contentInventory.ts) 接收装配包、章节登记及草稿快照，返回结构化结果；不直接读磁盘，不依赖浏览器。
2. **只读命令与文档入口（已实现）**：[查询工具](../../tools/contentInventory.ts) 负责读取与格式化；摘要默认简短，明细按需展开。JSON 保留条目版本、关联字段路径、卡面原文出处；结构内容的文件定位指向 TS 装配入口，审核条目定位到具体 JSON。
3. **基线核对与交付**：对照现有卡面看板、实际内容文件核对精确数量与名单；差异记录原因。清点 content/README 的旧状态，将实时统计指向命令，保留历史记录和人工计划。
4. **审查台页面（已实现）**：角色汇总、类型与范围筛选、条目折叠明细、警告、刷新与错误重试。覆盖率迁移已在 B2 完成；待生产计划结构化登记仍待后续批次。

## 6. 验证与验收

- 断言精确数量与内容 id：一卡多章、部分批准、缺对话未接入、招募/长线分栏、专属/多人/通用、无前缀话题、到达事件不误归所有人。
- 修订场景断言旧版仍已接入、新版待审、产量不翻倍；重复 id 与未知归属明确报出。
- 查询前后输入与工作区内容不变；稳定排序；摘要与 JSON 使用同一结果，JSON 能解析，错误参数非零退出。
- 先跑相关 Vitest、实际命令样例与类型检查，标「局部验证通过，待批次集成」。批次收尾复查数据装配与读取边界，执行基础检查；若仅新增只读统计且相关测试充分，无浏览器改动则不强制 E2E。公共装配代码若有行为改动，再按影响扩大回归。
- 不新增依赖、不创建另一份需人工同步的内容总账，不把最低覆盖达标写成内容质量通过。

交付标准：指定偶像一次查询得到分类数量与状态，展开即可定位每条内容及出处；新增/审批/修订后重新查询自动反映变化，统计不能修改任何审批状态。

## 7. 首次核对与边界

约会机制新增后，报告增加独立的 dateScenarios 列表和角色方案数量；CLI 明细与审查台“约会方案”筛选可查看方案 → 对话关联。方案不重复记作专属行动，正式方案当前为 0；具体接入顺序见 [约会说明](date-feature-plan.md)。

- 2026-11-04 源数据核对：28 人、29 张卡、110 章；真乃 2 张卡/8 章、1 条招募/1 条长线、2 个专属行动、9 个话题；「看她做饭」仍在 revisions，计待处理而非已接入。上述为验证基线，今后数量以命令为准。
- 卡按偶像与出处卡名去重；原卡总章数来自出处登记。重复章号、拆成多链会警告。不能仅凭 title 相同就合并不同偶像的卡。
- 对话主属和参与会重叠；NPC 话题列全局共享。无明确偶像归属的开场对话保留在待确认清单，不根据正文猜人。
- 未递归推断工作/商店/物品引用的所有间接关联；显式偶像引用保留路径。来源目录缺失或坏 JSON 报错，不将读取失败视为零内容。
- 此工具不替代内容形状、锚点或审批门禁；`content:coverage` 已在 B2 迁移显式关联口径，原数值门槛不变。统计测试接入 `npm test`；审查台页面由 `tests/review/inventory.spec.ts` 覆盖角色切换、待修改条目、筛选、刷新失败与恢复、返回队列。本批按局部交付验证，正式游戏全量留到批次收尾。
