> 上一稿是按"地区分组"想的；按你的澄清，改成**把地点本身合并成更少的节点**，
> 节点内部用描述与 `spots` 说明"这里有什么"。
> 这份只评估与列改动，不动代码。

## 2. 两种粒度

### M1（推荐）6 个节点

```text
事务所
朝雾站前      ← 车站 + 商业街
青叶练习街区   ← 练习室 + 录音棚
滨风海岸      ← 公园 + 泳池 + 医院
望丘大学
家
```

- 玩法差异保留：训练在练习街区、工作在录音棚（同一个节点，但行动挂在子场所上，见 §3）。
- 改动量：剧情步骤 25 条左右 + 工作 6 份 + 商店 1 家 + 日程若干 + 存档迁移。
- 玩家操作更少：从家去"站前"能同时看到车站与商业街的动作。

### M2（更像你举的例子）4 个节点

```text
市中心      ← 事务所 + 车站 + 商业街 + 练习室 + 录音棚
滨风海岸    ← 公园 + 泳池 + 医院
望丘大学
家
```

- 地图最干净，但**训练、工作、剧情全挤在市中心一页**：
  "去事务所"和"去练习室"不再有移动成本差异，节奏会变松。
- 改动量比 M1 少一点（引用更集中），但玩法代价明显。

**我推荐 M1**：它是"地点合并"，但保留了"练习室 vs 录音棚"这种玩法区分；
M2 更像把整张地图并成一张桌子。

## 3. 数据形状：地点里说明"有什么"

```ts
export type LocationSpot = {
  id: string;          // 'pool' / 'hospital'
  name: string;        // 泳池 / 医院
  description: string; // 一句话：这里具体是什么样
};

export type LocationDef = {
  ...
  /** 合并进来的子场所。只用于描述与检索，不是移动单位。 */
  spots?: LocationSpot[];
};
```

- 引擎只认 `locationId`（合并后的节点）。
- `spots` 给三样东西用：地点页描述、地图提示、`content:where` 检索、AI 写场景。
- 行动/事件/剧情**仍然挂 `locationId`**；如果非要区分"在泳池边"还是"在公园里"，
  写在场景文本里，不新增引用维度。

## 4. 检索：合并后 AI 怎么知道"这里有什么"

```bash
npm run content:where -- seaside
```

```text
地点  滨风海岸（seaside）
描述  这一带是海边的坡道与长椅……（合并后的地点描述）
子场所
  · 公园   长椅、喷泉、喂鸽子的人
  · 泳池   白瓷砖、遮阳伞、会起浪的那一池
  · 医院   大学医院的中庭，长椅旁有一小片花坛
可做  公园喂鸽子 / 街拍 / 环顾四周
剧情  巡的卡面「拍摄当天」（原泳池）
角色  真乃、灯织、巡、摩美々的作息会经过这里
路线  从 事务所 步行 22 分钟（office → 公园方向）
```

再配 `--route A B` 与 `--idol <id>`（同上一稿），写场景先跑命令，不凭印象。

## 5. 合并要动的清单（M1）

| 类别 | 具体 |
|---|---|
| 地点定义 | 新增 3 个合并地点 + `spots`；删掉/停用被合并的 5 个（station/shopping_street/practice_room/studio/pool/park/hospital 中的一部分） |
| 行动 | `locations` 数组改合并 id（约 15 条行动） |
| 剧情步骤 | 25 条左右（含 3 章卡面：泳池、车站、商业街） |
| 日程 | 18 条日程的 `locationId` |
| 工作 | 6 份（录音棚 → 练习街区） |
| 商店 | 1 家（商业街 → 站前） |
| 交通 | 巴士枢纽从 `station` 改到 `站前` |
| 地图 | 节点与步行边重画（6 个节点） |
| 存档 | `SAVE_VERSION` 19：地点 id 重映射（含 scheduleOverrides） |
| 测试 | 4 条 E2E 的 `jumpTo` 地点 + `productionMap.test` + 章节锚点位置 |

**为什么必须迁移存档**：玩家可能正好站在 `pool`，或日程覆盖写着 `park`；
不迁移的话加载后地点 id 不存在，页面会"她不在这里"。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 合并后行动页变长（站前 7 个行动） | 行动按子场所分组显示（P1 再做），先接受 |
| 剧情文本提到具体地点，引用却指向合并 id | 文本不变；`chapterSources.locationId` 改成合并 id，锚点照旧 |
| 日程语义变粗（练习与收录同一节点） | 用 `label` 区分（"练习""收录"），presence 只看节点 |
| 存档 id 失效 | schema 19 迁移 + 测试覆盖 |
