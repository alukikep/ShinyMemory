# Phase C 之后的路线图

## 当前状态

已完成：

- Phase A：冷白/浅青视觉 token、顶部三色线、图标系统；
- Phase B：地点场景卡移入侧边栏；
- Phase C：Q 版头像接入侧边栏、名册、偶像页；
- 地图只在地点菜单（`plan`）显示；
- 场景卡信息条按日期/时间/金钱三行排列；
- 行动数已从玩家界面移除。

当前页面结构：

```text
顶部栏：品牌 + 重开
三列：
  左：场景卡 + 状态 + 当前偶像 + 名册入口
  中：场景标题 + 行动 + 地图（仅 plan）
  右：日志
```

## 原计划 vs 现在

原计划：

```text
D 地图/公交视觉
E 固定侧边栏
F 响应式/可访问性
```

现在建议调整为：

```text
C.1 地点角色条头像（可选）
D 固定侧边栏 / App Shell
E 地图/公交视觉
F 响应式/可访问性
G 日历与内容扩展
```

## 为什么把 D/E 对调

### 1. 地图范围已经收窄

地图现在只在地点菜单显示，其他阶段隐藏。

地图视觉仍然需要做，但优先级下降了：

- 不再需要处理事件/互动阶段的“禁用地图”；
- 不需要为其他 phase 设计地图状态；
- 先把页面骨架定下来，地图后面只做一次。

### 2. 顶部栏内容变少

时间、金钱、行动已经移到侧边栏。

顶部栏现在只剩：

```text
ShinyMemory              [重开]
```

如果先做固定侧边栏，可以把品牌、导航、状态统一到一个完整 shell 里，避免后续再改。

### 3. 侧边栏会继续加功能

后续可能需要：

- 地点；
- 名册；
- 地图；
- 任务；
- 存档；
- 设置；
- 当前偶像；
- 制作人状态。

当前左侧仍是一个 `aside.panel`，不是完整导航；继续加功能会越来越挤。

### 4. 地图宽度会受 shell 影响

固定侧边栏会改变中间列宽度，地图 SVG 和 pin 尺寸都要跟着调整。

先定 shell，再做地图，避免地图做完后重排。

## C.1 地点角色条头像

这是 Phase C 的补充，工作量很小。

当前地点页的偶像入口：

```text
樱木真乃 偶像 信任 E 训练 →
```

可以加一个 32 × 32 的 Q 版头像：

```text
[头像] 樱木真乃 偶像 信任 E 训练 →
```

范围：

- `ActorView.avatar`；
- `buildActorViews` 对偶像读取 `IdolDef.avatar`；
- `ScenePanel` 的 actor-entry 加头像；
- NPC 没有头像时使用首字 fallback。

估算：0.5 天。

## D：固定侧边栏 / App Shell

状态：已完成。

### 目标

把当前“左栏状态面板”升级为真正的全局侧边栏，为后续功能留位置。

### 桌面结构

```text
┌────────────────────────────────────────────┐
│ 固定侧边栏 236px │ workspace               │
│                  │ 顶部栏：面包屑/状态/重开 │
│ 品牌             │                        │
│ 场景卡           │ 主内容                 │
│ 状态             │  中列：场景/行动/地图   │
│ 当前偶像         │  右列：日志             │
│ 主导航           │                        │
│ 制作菜单         │                        │
│ 版本/说明        │                        │
└────────────────────────────────────────────┘
```

### 侧边栏顺序

```text
品牌
地点场景卡
日期 / 时间 / 金钱
共享状态
当前偶像
主导航
  - 当前安排
  - 偶像名册
  - 地点地图（仅 plan，滚动到地图）
  - 设置（占位）
底部版本
```

### 顶部栏

从：

```text
ShinyMemory              [重开]
```

改成：

```text
283 事务所 / 当前安排       进度状态   [重开]
```

品牌移入侧边栏。

### 移动端

- 侧边栏变成顶部品牌 + 状态；
- 主导航变底部栏；
- 场景卡仍在状态之前；
- 地图只在 plan 显示；
- 避免固定侧边栏在手机上占用过多高度。

### 风险

- 当前侧边栏内容高度约 600px，固定后需要内部滚动；
- 改动 `App` 的布局结构，影响所有页面；
- 地图/日志宽度会变化；
- 移动端需要重新排顺序；
- 不应顺手加入新页面，只做 shell。

估算：3–4 天。

## E：地图与公交视觉

状态：已完成。

### 地图

保留规则网格，只做视觉层：

- 点阵/浅色街道背景；
- 半透明建筑块；
- 圆形图标 pin；
- 当前地点实心青蓝；
- 相邻地点白底青边；
- 路线虚线/实线；
- 图例；
- 地图只出现在 plan。

### 公交/出租车

当前已经有：

- 固定票价；
- 固定时间；
- 目的地弹窗；
- 图标。

剩余：

- 路线描述；
- 右侧票价对齐；
- 底部现金；
- 弹窗与地图的视觉统一；
- 可选车程事件入口（后续）。

估算：1–2 天。

## F：响应式与可访问性

- 1440 / 1024 / 768 / 390 四档；
- 侧边栏内部滚动；
- 弹窗焦点管理；
- 键盘可操作；
- 图片 alt / fallback；
- 对比度；
- 减少动画；
- 无横向溢出。

估算：1–2 天。

## G：之后的系统和内容

这些不属于当前视觉迁移，但会受 shell 影响：

### 日历

当前日期行只有：

```text
第 1 天
```

未来可显示：

```text
2026年10月25日 · 星期日
08:00
¥3,000
```

需要新增年/月/日/星期数据，不只是视觉改动。

### 更多偶像

Q 版头像已经准备好 26 张，但当前游戏只接入真乃/灯织。

新增偶像需要：

- 角色定义；
- 日程；
- 训练/工作；
- 事件；
- 立绘/头像路径；
- 存档兼容。

这是一个内容/系统阶段，不建议和视觉 shell 混在一起。

### 更多地点

地图、场景卡、移动图都需要跟着扩展。

## 推荐顺序

如果没有新的视觉反馈，建议：

1. **C.1** 地点角色条头像（0.5 天）；
2. **D** 固定侧边栏 / App Shell（3–4 天）；
3. **E** 地图/公交视觉（1–2 天）；
4. **F** 响应式/可访问性（1–2 天）；
5. **G** 日历/角色/地点扩展（后续）。

总计约 **5–8 天**。

## 暂不做

- 不恢复主列大 Hero；
- 不在非 plan 阶段显示地图；
- 不把 26 名角色一次性接入游戏；
- 不先做日历系统；
- 不在 shell 阶段加入新玩法；
- 不用全身立绘替代 Q 版小头像。

## 需要确认

1. 是否先做 C.1 地点角色条头像；
2. 是否接受固定侧边栏作为 D；
3. D 阶段是否只做 shell，不新增页面；
4. 地图/公交视觉是否排到 E。
