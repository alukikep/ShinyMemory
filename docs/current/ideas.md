## 1. 经济与商店

### 1.1 事务所汽车（永久限购）

**一句话**：花一大笔钱买一辆事务所的车，之后在城市内点对点免费快速移动，不用再坐公交/出租车。

**为什么**：后期钱多、地点多，跑图会变成重复劳动；汽车是“花钱买时间”的长期目标，也符合“钱买选择，不买胜利”。

**代价**：

- 现在 `takeTransit` 是固定路线 + ¥100 + 5 分钟；走路走 `WALK_EDGES`。
- 汽车需要一个新的移动模式：要么 `carTravel(state, locationId)` 走最短路并免车费，要么给 `takeTransit` 加“已购车”分支（免 fare + `travel` 倍率）。
- UI 要加一个“开车前往”的入口；地图上要能选任意可达地点。
- 存档只需 flag（`owned.agency_car`）或 `ownedEquips`，不用新字段。

**风险**：

- 公交/出租车系统会被绕过；如果汽车太快太便宜，地图的“距离感”消失。
- 点对点移动和剧情触发（到达事件）要接同一套检查链，不能绕过 `arrival`。
- 价格必须很高，否则前期就破坏交通取舍。

**状态**：灵感，未实现。

### 1.2 永久成长道具

**一句话**：一次性购买、永久生效的成长类道具，比如训练手册、跑鞋、相机镜头。

**为什么**：给“钱多到没处花”的后期一个一次性目标；比重复买礼物更有“收藏/建设”感。

**代价**：

- 不建议塞进 `inventory`（数量语义）；走 `EquipDef` / 饰品槽更合适。
- 需要购买入口：`EquipDef.price` + 商店 `sells: 'equips'`，或 `maxPurchases: 1` 的功能商品。
- 效果用现有 `Modifier`：`trainingExp` / `staminaCost` / `travel`。

**风险**：

- 直接卖数值会变成“付费变强”；效果要小（5–10%），价格要高。
- 三个同类叠加会通胀；内容体检要限制同 key 的乘算项数。

**状态**：灵感，未实现。

### 1.3 更长冷却的商品

**一句话**：除了 24h / 72h，还可以有 168h（一周）甚至更长的商品，用于强礼物、限定道具。

**为什么**：给“攒很久买一次”的期待，不用永久限购也能控制产出。

**风险**：等待太长会变成“上线点一下”的打卡；需要配合更强的反馈（专属剧情/礼物反应）。

**状态**：灵感，未实现。

### 1.4 事务所经营：月度工资 + 维护费 + 叶月成长（待制作）

**一句话**：把事务所变成每月有固定支出的经营体：偶像工资、叶月工资、维护费；叶月的等级解锁咖啡和事务所 QoL。

**当前完成度**：按完整经营循环估算 **不到 30%**。
已有：开局资金、零工/偶像工作收入、训练/礼物/设施支出。
未做：月度工资、维护费、月度结算、负数债务、更多收入途径。

**为什么**：一次性设施出口用完后，钱会重新堆积；月度工资是可持续的压力，也能让“招多少人、接多少工作”变成真正的经营选择。

**当前数值草案（未实现）**：

- 偶像工资：300/月起，每月上涨，封顶 2,000/月；
- 28 个偶像满工资：**56,000/月**（不是 4.8 万；4.8 万对应 24 人或平均 1,714）；
- 叶月工资：初始高于偶像，草案 **800/月**，随事务所等级上涨；
- 事务所固定维护费：5,000/月；
- 当前 4 份工作上限日收入约 2,200，月收入约 66,000；工资+维护约 61,000，训练 6 次/天还要 27,000，**当前收入结构下会月亏约 22,000**。

**待定规则**：

- 第一个月免工资/维护，或按天折算；
- 工资月涨幅（建议 +50/月，避免过早压死）；
- 叶月升级是否加工作数：会和工作区 1→4 重复，需二选一；
- 咖啡“每天一次”：现在是 12 小时冷却（一天可两次），要改 24 小时或日界重置；
- 负数金钱：当前 `clampState` 会把钱钳到 0，必须移除钳制；负数时禁止付费行动，但零工/工作仍可做，不收利息；
- 月结前 3–7 天预警。

**风险**：

- 28 人 ×2,000 + 5,000 维护，按当前收入会挤掉训练；要么降低封顶（约 1,000–1,200），要么先加新的月收入途径；
- 叶月升级如果加工作数，但月薪只涨一点，会成为无脑必买；
- 固定工资高、收入渠道少时，后期可能变成“只能工作、不能训练”。

**状态**：待制作构想，未实现，不改当前数值。

## 2. 设施

### 2.1 设施管理室做成真房间

**一句话**：现在 v1 用练习室里的「设施管理室」面板；以后可以做成一个真正的子地点 `practice_office`，走进去再升级，顺便放对话和场景。

**代价**：

- 新地点 + `mapX/mapY` + 步行边 + `productionMap.test` 的可达性检查；
- 如果做成 `practice_room` 的成员，还要把练习室改成 `area`，影响现有地图与测试。

**风险**：为了一个面板改地图不划算；等办公室真的要有剧情时再做。

**状态**：灵感，未实现。

### 2.2 施工期

**一句话**：升级后不是立刻生效，而是“施工 N 天”，到点才换新训练。

**代价**：升级命令写 `scheduleEvent`，到期事件改 `vars`；UI 显示“施工中”。

**风险**：玩家可能忘记；需要手册/面板明确倒计时。

**状态**：灵感，未实现。

### 2.3 房间命名 / 装饰

**一句话**：给三个练习室改名、换装饰，纯外观 sink。

**风险**：没有玩法收益，容易变成“花完就忘”；需要收藏/成就支撑。

**状态**：灵感，未实现。
