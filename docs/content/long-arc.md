# 长线剧情执行手册

> 适用于**一条跨多步、有分支、有结局**的剧情线（对标：真乃「唱不出来的那天」、
> 灯织「千里的距离」、巡「不重要的事，选不出来」）。
>
> 卡面改编（一章 = 一段 commu）见 [card-adaptation.md](card-adaptation.md)。

---

## 0. 长线和卡面章的区别

| | 卡面章 | 长线 |
|---|---|---|
| 素材 | 一张卡的**一段** commu | 原作的**育成章节**（W.I.N.G. / G.R.A.D. / S.T.E.P.）或我们自己设计 |
| 结构 | 1 步，一坐读完 | **3–5 步**，跨天推进 |
| 分支 | 选项后走不同分支到章末 | 用 `var` 记录选择，后续步骤**台词变体** |
| 结束 | 分支各自结束 | 必须有一个收束（flag） |
| 手册 | 一条 | 一条，显示"第 N 步 / 共 M 步" |

---

## 1. 选材：从原作哪一章来

```bash
npx tsx tools/scriptExport.ts <剧本编号>
```

剧本编号从原作目录的 csv 行 id 取前 9 位。产物在 `.cache/shiny/`（不提交）。

**长线的素材通常是一整章**（如 G.R.A.D. 的三章），不是一段。所以先读完整章，
把"这章在讲什么冲突"写成一句话，再拆步。

> 参考：灯织「千里的距离」来自 G.R.A.D. 三章——
> `そこには千里の距離があるよう` → `明かりがさす方へ` → `そしてまた歩き出そう`。

---

## 2. 先写大纲（beats），再写对话

**不要**一边写对话一边想结构。先定这三件事：

```text
① 起点：她现在的状态是什么（一句）
② 转折：什么事件打破它（一句）
③ 落点：她最后变成了什么（一句）——注意不是"解决了"，是"变了"
```

然后拆成 3–5 步，每步写成一句话：

```text
步1 她看到广告牌（落差出现）
步2 她来问"两人有的而我没有的是什么"
步3 她没有想通，但继续走
```

**每一步 = 一段对话，一次触发。** 不要在一段对话里塞两个转折。

**每一步都要写 `source`（剧本编号）**——长线的素材来自 G.R.A.D./W.I.N.G. 的某一章，
写不出编号就说明还没读原文。`content:board` 会检查它存在。

## 3. 步与节奏

```ts
{
  id: 'hiori-gap',
  idolId: 'hiori',
  title: '千里的距离',
  cadenceDays: 1,          // 隔几天能推进一步（1 = 每天）
  workPolicy: 'open',      // 章进行期间能否接工作
  steps: [
    { locationId: 'shopping_street', timeWindow: {…}, dialogueId: '…', actionLabel: '橱窗前的广告牌' },
    { locationId: 'studio',          timeWindow: {…}, dialogueId: '…', actionLabel: '收录结束后她没走' },
    { locationId: 'practice_room',   timeWindow: {…}, dialogueId: '…', actionLabel: '她按下了播放键' },
  ],
}
```

| 参数 | 什么时候改 |
|---|---|
| `nextStepDelayDays` | 需要"过几天再说"时（默认 1） |
| `cadenceDays` | 节奏（1 = 每天可推进；7 = 每周一次） |
| `workPolicy: 'blocked'` | 她这段时间**确实不能工作**（闹掰、生病） |
| `endLocationId` | 结束时玩家该在别的地方（可选，默认不搬） |

---

## 4. 分支：用 var，不用多步

长线的分支**不是**"每条分支走一套后续步骤"，而是：

```text
步2 的选项 → 写一个 var（如 hiori.gapApproach = 1/2/3）
步3 的台词 → 按 var 出不同版本（textVariants）
```

**textVariants 必须精确匹配**：

```ts
when: [
  { kind: 'varAtLeast', key: 'hiori.gapApproach', value: 2 },
  { kind: 'varAtMost',  key: 'hiori.gapApproach', value: 2 },
]
```

只写 `varAtLeast` 会让三个变体全部命中第一条——真实踩过，三条不同分支永远显示第一种。

**每一步最多 1 个选择点**，和卡面章同一条规矩。

---

## 5. 落点：必须收束

长线结束时要留下可追踪的痕迹：

```ts
effects: [
  { kind: 'sharedStat', stat: 'stress', delta: -20 },
  { kind: 'var', key: 'hiori.gap', op: 'set', value: 3 },
  { kind: 'flag', key: 'resolved.hiori.gap', value: true },
]
```

**flag 是给后续内容用的**：其他剧情/工作可以用它判断"这条线走完了没有"。
没有 flag 的长线等于没结束。

---

## 6. 审查顺序

```text
步1 对话 → 送审
步2 对话 → 送审
步3 对话 → 送审
（全部通过后）把链接进 STORY_CHAINS
```

和卡面章一样：**先过审，再接结构**。反过来会让 `BASE_PACK` 引用不存在的对话。

**三条既有长线已经迁进审查台并通过**（真乃 / 灯织 / 巡，各 3 段对话，共 9 条）。
所以现在**所有剧情对话都走审查台**，没有例外。迁移方式见下：

```text
1. 把 TS 里的对话导出成 draft（kind: dialogue）
2. 从 TS 删除对话声明、从对话数组里移除
3. 把链从 STORY_CHAINS 移到 chapters/index.ts 的 PENDING_CHAPTERS，并标 kind: 'arc'
4. 生产包只挂"对话已批过"的链 → 批到一半不会引用不存在的对话
```

**为什么这样设计**：长线和卡面章一样，对话是 approved 内容、结构是 TS。
结构不能进 BASE_PACK（会报 dialogue-ref），所以统一在 `productionPack` 里拼，
并按"对话是否已批"过滤。

## 7. 机器会拦住你的事

| 规则 | 现状 |
|---|---|
| 对话 id 必须存在 | `content:audit` |
| 变体必须精确匹配 | 无（靠自觉，见 §4） |
| 每步 ≤1 个选择点 | 仅卡面章校验；长线**待补** |
| 步数、地点、时间窗合法 | `content:anchors` 的结构校验 |
| 收束 flag | 无（靠自觉，见 §5） |

> 长线的形状校验（步数、分支数、收束 flag）还没进机器。补的时候参照卡面章的
> `validateChapterShape`，加一个 `kind: 'arc'` 分支。

## 8. 一次真实拆解：巡「不重要的事，选不出来」

| | 内容 |
|---|---|
| 素材 | W.I.N.G.編 `大切、選べないから。` |
| 起点 | 她把所有请求都接下来，累到站不稳还说"没事" |
| 转折 | 制作人发现她连"取消工作"都不肯 |
| 落点 | 她第一次说"下个休息日的比赛，我可以不去吗"——**不是学会拒绝，是第一次为自己选** |
| 步数 | 3 步（公园球场 → 事务所 → 练习室） |
| 分支 | 步2 三选一 → `meguru.burdenApproach` → 步3 三种开场白 |
| 收束 | `resolved.meguru.burden` |

**关键**：落点不是"变强了"，是"变了一点点"。写长线最容易犯的错是让她一步跨完。
