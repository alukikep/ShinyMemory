# 约会功能实施计划

> 2026-11-05 · 机制、fixture 样例与界面已实现，批次验证通过；正式角色约会剧情尚未接入。以下为已确认设计和实施记录。

## 1. 已确认规则

| 项目 | 决定 |
|---|---|
| 关系数值 | 沿用偶像信任；失约只扣当前等级经验，不降级，最低为 0。经验已为 0 时处罚可能为 0，不补扣其他数值 |
| 日程 | 整天使用 replace-day 覆盖，仅在约会时段出现在指定地点；保留工作、剧情和受保护日程冲突检查 |
| 费用与取消 | 确认成功时扣费；确认后不能取消，不提供取消命令或退款按钮 |
| 首批范围 | 完整机制与明确标记的测试样例；正式角色剧情由内容模型生产、独立初审、人工批准 |
| 默认预约规则 | 在制作人的家打电话，只邀已招募偶像，只预约今天；每天全局最多成功预约一次，预留出行时间 |
| 赴约方式 | 在约定地点与赴约窗口内主动点击开始，及时开始即算赴约；不靠随机事件命中 |

普通约会作为预约活动，不占全局两条剧情链名额；与剧情的日程占用仍需协调。第一批不增加独立恋爱值、未来日期预约、改约、多人约会或新的地点。

## 2. 可复用能力与需要补齐的部分

- 日程解析、`ActorState.scheduleOverrides`、`canReplaceDay` 及次日清理已存在。整天覆盖会隐藏当天全部周模板，不仅隐藏约会时段；已有覆盖或受保护模板会使整天无法预约。
- 工作提供预约、到场与逾期补结算案例，可借鉴流程；约会需要独立状态，不能冒充工作或只存一条覆盖。
- 对话引擎已有目标偶像、条件选项、效果及结束返回；约会需增加结束关联与时间结算，不能通过普通对话结束直接认定任意预约已完成。
- `applyAttributeExp(..., 'loss')` 已满足本次不降级规则。对话选项可调用信任效果；效果目标必须绑定预约偶像，不依赖玩家此时选中了谁。
- 时间推进、初始读档、存档槽读档及调试跳时都需要共用一次性逾期结算。当前覆盖会在跨天时先被清理，因此处罚必须依据独立预约记录，而不能查剩余覆盖猜测是否失约。
- 地点遵守 [地点入口说明](../systems/location-portals.md)：预约实际成员地点，排除私有 home、不可达地点及普通地区入口；事务所例外不自动代表适合约会，采用配置白名单。

## 3. 时间、费用与奖励建议值

以下是测试和初始配置建议，集中配置，后续可调整，不作为新增硬规则：

- 每天提供整点开始的候选，确认时距离赴约开始至少 30 个游戏分钟；候选须满足从家出发的可达路线与所需路程，不只检查地点存在。
- 赴约窗口 30 分钟，实际约会耗时 60 分钟；预留日程覆盖整个窗口与耗时。所有预约不跨夜，预留结束不晚于 22:00。
- 例：选择 14:00，允许在 `[14:00, 14:30)` 开始，日程位置为 `[14:00, 15:30)`。14:30 尚未开始即失约；14:29 开始可完整约会至 15:29，不会中途判失约。
- 预约费建议 ¥1,000。确认后离开或睡过赴约窗口，费用不退；没有足够金钱、可用内容或合法时间时不产生预约和扣费。
- 测试样例单次约会的不同选择给信任经验 0/10/20，失约扣 10；使用现有合法 ExpTier，不引入另一套经验公式。真实剧情奖励由内容配置，但总奖励预算需有上限校验，不能每个选项无限累加。

电话面板浏览、切换选项不消耗时间，不扣钱；预约动作本身第一版不额外推进时间。实际约会时间在对话正常结束时统一推进一次。对话阅读和中途读档不消耗现实时间对应的游戏分钟。

## 4. 数据与业务边界

### 预约记录（运行时，入存档）

拟新增 `DateAppointment`，包含稳定 id、方案 id、偶像 id、地点 id、当日、赴约起止分钟、预留结束分钟、实际耗时、对话 id、已支付费用、处罚档位与状态。状态为 `scheduled → inProgress → completed` 或 `scheduled → missed`；没有玩家取消分支。

GameState 保存当前/最近预约，以及成功预约所用日期。每日次数按成功预约事实计算，完成或失约后仍不能在当天再约。单次全局最多一条，首版不存无限增长的历史列表；结果日志保留记录，终态数据在跨日且安全时清理。预约覆盖 id 必须关联预约 id，不能删其他工作或内容覆盖。

拟新增 `dateAppointments.ts`，提供纯预约资格/候选时段评估、状态转换与逾期判定。UI 与命令使用同一资格结果；sim 只负责接线与效果执行。若抽出日程占用辅助函数，只处理本功能涉及的冲突，不借机实施完整 C 重构。

### 约会方案（内容结构）

拟新增 `DateScenarioDef`：稳定 id、偶像、地点、对话引用、费用/时间配置、处罚与奖励预算等。作为 TS 结构进入 ContentPack/ContentIndex（缺省为空），真实对话继续使用现有 dialogue 审批类型，不新增一种绕过审批的台词入口。

正式接入顺序为：生产并人工批准对话 → 登记方案结构 → 严格校验引用 → 源包接入。第一批仅在 fixture 中配置合成测试对话，明确是机制测试，不引用或仿写角色原文，不移入 approved。正式方案列表为空是有效状态。

内容校验检查角色、地点、对话目标与引用、时间范围、费用、奖励预算及重复 id；覆盖率不把一个约会方案再算成一份普通专属行动。内容档案应能列出“约会方案”及其对话关联，区别方案数量与对话产量；扩展报告字段时同步契约和 CLI/UI 测试，不重复计作品。

## 5. 界面与结算顺序

1. **电话入口**：仅制作人家中的可操作阶段出现；面板依次选偶像、已有内容的地点、当天时段，展示费用、赴约窗口、预计耗时、整天覆盖说明、不可取消及不降级处罚规则。
2. **确认**：拟命令 `bookDate` 只接收方案/时段等选择，不信任 UI 传入的价格与奖励。重新检查在家、无进行中对话/强制休息、已招募、每日次数、资金、内容、时间与日程冲突；通过后同一次状态转换扣费、写预约和 replace-day 覆盖。拒绝保持状态不变，连点不能重复扣费。
3. **占用协调**：预约前检查保护日程、既有覆盖/工作及同偶像剧情日。成功后，同日同偶像的新工作、剧情启动和后续覆盖写入也必须遵守预约占用；在执行前拒绝冲突，不能只在电话面板禁用。需要强制抢占的内容不在第一版支持范围，不允许静默覆盖后处罚玩家。
4. **赴约**：拟命令 `startDate` 同时检查预约状态、地点、窗口、可操作状态与目标；不依赖当前焦点偶像，也不因约会剧情链名额已满而隐藏。先锁定 inProgress，再打开指定对话；失败不能留半条进行中记录。
5. **对话结束**：选项效果绑定预约偶像；借用现有节点进度与效果执行机制，读档不重新打开首节点。正常结束仅完成一次预约、推进一次约会耗时；推进期间不把 inProgress 判成失约。完成状态不能重新领取奖励或重复开始。
6. **失约**：对仍为 scheduled 且游戏时间已到赴约截止的预约扣一次当前等级信任经验，置 missed，记明确日志；睡觉、长行动、直接跨多天、读档/调试跳时均遵守同一绝对截止时间。离线经过的现实时间本身不算失约。
7. **覆盖与清理**：当天终态也保留整天覆盖语义直到次日自动清理，不因完成/失约立刻恢复原周模板。约会时段以外偶像不出现在原日程位置；日期清理与次数更新不清除正在进行的对话关联。

拟在时间推进/读档统一处理预约终态；不得把核心处罚放在可丢失、异常会被吞掉的 GameEvent 监听器或 UI useEffect 中。

## 6. 存档与内容分工

- 当前 SAVE_VERSION 为 20；若实施前没有其他版本变更，本功能迁移至 21，旧档默认无预约/未用当日次数；不因新增可选功能提高 CONTENT_EPOCH。
- 进行中对话与预约关联一起存档；恢复当前节点，不重扣预约费，不重复执行已完成节点效果。加载后多次结算、跨多天结算与先清覆盖后结算的结果须一致。
- 架构侧负责机制、配置约束、测试样例、交接字段与内容档案入口；真实角色台词、合理选项及角色卡依据交给内容生产与独立初审，最后由人批准。约会为原创剧情，不要求剧本 `source`；内容模型不修改约会计时、存档或惩罚机制。
- 正式包暂时显示“暂无可预约内容”或对应禁用原因，不展示 fixture 人物台词，不向未接入内容的角色收费。交付称“机制可验证”，不称“正式角色约会内容已上线”。

## 7. 实施分段与验收

| 阶段 | 范围 | 局部验收 |
|---|---|---|
| P1 | 纯规则、记录、时间边界与配置形状 | 固定状态测试；所有时间/次数/冲突拒绝原因精确断言 |
| P2 | 预约/赴约命令、日程覆盖、对话结束、逾期结算和迁移 | 扣费与覆盖同时成功；读档与跨日只结算一次；同偶像与焦点切换正确 |
| P3 | 电话面板、地点赴约入口、日程表提示、档案接线 | 契约测试及 fixture 单条 E2E；正式无内容空态 |
| P4 | 内容生产接口说明与批次集中复查 | 基础检查、fixture 约会流程、最终正式包完整 E2E；真实内容另批审批 |

必要断言包括：

- 钱不足/非法参数/过去时间/路程不够/未招募/已有当日预约/保护与工作剧情冲突时不扣钱、不写覆盖；重复确认只扣一次。
- 赴约起点包含、截止点排除；正好截止、睡过窗口、长行动跨过窗口、跨多天、加载过期记录都只扣一次；经验不足扣到 0、等级不变。
- 开始约会后时间推进不误罚；中途存取档、切换焦点偶像后奖励仍落到预约对象，结束只推进一次时间、只完成一次。
- 整天覆盖、窗口内位置、窗口外不在场、终态当天不恢复模板、次日恢复及其他覆盖不被误删。
- 普通两条剧情名额占满仍可赴约；同偶像日程冲突仍被阻止。方案与对话关联及奖励预算准确，fixture 内容不进入正式包。
- E2E 同时断言入口出现、扣费/预约/选项奖励/完成字段；失约用例断言具体经验和一次性日志，不只断言页面不报错。

本计划不添加未实现命令到 package.json。实施中按相关 Vitest → 对应模式构建 → 单条 E2E 推进，标记局部验证；本功能涉及共享时间结算和存档，批次收尾对最终版本执行 `npm run content:board`、`npm test`、`npm run build` 与正式完整 E2E，并按改动补 fixture 约会用例。配置切换先构建对应模式，多个 Playwright 配置顺序运行，不每个小改各跑一遍全量。

## 8. 实施与内容交接

- `dateAppointments.ts`：共享资格评估、时间候选、开始条件与日程保护；sim 中 bookDate/startDate/completeDueDates 接入状态转换，对话结束统一推进时间。全部玩家命令通过日程保护检查，出现覆盖冲突时整条命令回滚，不保留已支付费用外的半次效果。
- `DatePhone.tsx`：家中电话入口、偶像/地点/时段、费用、不可取消、信任不降级说明及空态。日程表使用已有动态覆盖展示“约会预约”；进行中的剧情日不会盖掉约会显示。
- 正式配置入口为 `src/core/content/dateScenarios.ts`，当前空数组。fixture 仅配置“【机制测试】公园约会”及 0/10/20 三种测试选择，不属于角色剧情，不进入 approved。
- `dateValidation.ts` 接入 `auditPack` 与构建门，拒绝未知角色/地点/对话、私有 home、普通地区入口、非法费用时间、重复方案 ID、超预算及循环奖励。第一版对话效果只允许信任经验、flag 和日志；每个选择节点必须保留无条件选项，避免进入后无法结束。
- 存档版本已从 20 升至 21，内容纪元保持 3。旧档没有预约；新档的预约、每日次数、进行中对话关联正常保存。初始读档、存档槽读档及调试跳时均补结算；仅普通浏览或现实离线不推进约会时钟。
- 档案报告增加 dateScenarios 列表与每人方案数量，审查台提供“约会方案”筛选；方案与现有对话关联展示，不另算成一份专属行动。

真实内容交接时，生产者提交：目标偶像、公开地点、对话草稿及角色卡依据（引用具体原作设定时再附原文依据）、选项因果、各分支信任效果和奖励总预算。约会属于原创剧情，不要求 `source` 或剧本编号；但不得编造原作事实。独立初审只提问题与建议，由人批准对话后，架构侧登记 DateScenarioDef 并跑校验；不得将 fixture 台词复制成正式剧情。内容生产者不修改状态、预约费用结算、失约或存档逻辑。

拟登记示例字段为：id/title/idolId/locationId/dialogueId/fee/durationMinutes/arrivalWindowMinutes/penaltyTier/rewardBudget。费用必须为正整数，时间为正整分钟，最大路径奖励不超过方案预算（预算上限 20）。同一时间地点可有多个方案，但玩家一天只能成功预约一个；正式配置不把尚未批准的对话挂入源包。

手动体验机制样例：先 `npm run build:fixture`，再 `npm run preview`，打开带 `?debug=1` 的页面。fixture 真乃初始已招募，现有周模板在星期日空闲；可跳至第 7 天，回家后打开电话并选择公园和剩余合法时段（资金至少 ¥1,000）。正式构建仍显示空态，不能据此声称真实约会剧情已上线。
