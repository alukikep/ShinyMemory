## 4. 接下来的计划

具体阶段拆解见 [统一属性与上下文整理计划](plan-unified-attributes.md)。本节只记录优先级。

### P0：真乃正式内容基线

目标：让真乃从“可招募”进入“可持续游玩”。

工作：

- 招募后的日常对话
- 真乃的事务所/练习室/录音棚/公园小场景
- 真乃对制作人的称呼、语气、距离感
- 真乃的关系里程碑
- 真乃对训练、工作、休息的反应
- 不加入 WING 竞赛系统，只保留相遇剧情的叙事参考

验收：

```text
新游戏 → 序章 → 两次相遇 → 招募
招募后连续游玩 3–7 天有稳定内容
真乃在不同地点有符合人设的反馈
```

### P1：上下文整理与统一属性 · 已完成

方案见 [统一属性与上下文整理计划](plan-unified-attributes.md)，P0–P3 全部完成。

- ✅ 上下文整理（`selectedIdolId`、显式 `idolId`、`jobs` 必填、`STAT_MAX` 清理、存档 13）
- ✅ 多目标行动（`all-present-idols`、`pendingResults`、fixture `group_greeting`）
- ✅ 统一属性（`AttributeRef`、`terms` + `combine`、制作人摄影、存档 14）
- ✅ 验收（fixture `demo_recording` / `photo_shoot` / `cover_shoot` 覆盖三种形态）
- ✅ 制作人体能属性（体力上限 100–250、消耗倍率 1.00–0.80、测试事件验证）
- ✅ 双人剧情启用（锚定行动的触发、2 专属 + 1 通用、内容预算校验、fixture 统一训练）
- ✅ 事件→对话桥（`openDialogue` 统一入口、`dialogueId`、多人对话参与者、`{a}{b}` 模板）
- ✅ 存档槽（多槽元数据、旧手动存档自动迁移、新建/覆盖/读取/删除、导出/导入）
- ✅ 内容体检（引用完整性、组合戏规则、内容预算、flag 读写一致性）

这一阶段不做正式内容，只做引擎能力。剩余可选项在计划的 P4。

### P1：训练设施升级（暂缓）

类型：**内容/数值工作**，不是架构问题。当前架构已经能表达：

- 行动的实际消耗统一走 `activityCost(state, activity)`，房间等级在这一层做修正即可。
- 行动时长统一走 `activityDuration(state, activity)`（已抽出，当前直通内容值），等级影响时长时只改函数体。
- `ActivityDef` 的 `cost` / `durationMinutes` / `effects` 都是数据，升级表可以独立放置。
- 新状态只需要 `GameState.facilities`（或单值 `roomLevel`）+ 一次存档迁移。

暂缓原因：它会**同时**影响训练费用、时长、EXP，需要单独配一张平衡表；正式内容还没上量，升级了也没有可感知的收益。

将来要做时的工作：

- 练习室增加升级入口，VO / DA / VI 分房间等级
- 升级消耗金钱
- 等级影响费用、时长、EXP
- 有效活动解析统一显示和结算

### P1：制作人手册 · 已完成

参考炸弹小队手册的**机制**（不是外观）：追踪进行中的任务/剧情链，结束后归档。

动机不是“记进度”，而是补一个信息死角：`getEligibleStory` 只在地点、时间窗、最早天数三者同时满足时才露头，真乃第一次相遇后那两天，游戏完全没有出口告诉玩家“两天后下午去公园”。这个事实其实已经在 `nextEligibleDay` 里，只是没人读。

已落地：

- `handbook.ts`：`buildHandbook` 把剧情链投影成条目（等候 / 受阻 / 时段 / 可前往 / 完成），`describeCondition` 把未满足条件翻成人话
- 侧栏「手册」+ 进行中条数角标；归档按偶像分组折叠
- `StoryChainDef.revealWhen`、`StoryChainStep.when` / `effects`（不引入 `requires`，与 `when` 重复）
- `getEligibleStories` 返回全部候选，同一地点不再静默吞链
- 新增 `moneyAtLeast` / `idolStatus` / `hasItem` 三个 `Condition`（16 → 19 种）

存档与内容纪元均未变动。方案见 [制作人手册计划](plan-producer-handbook.md)。

### P2：新地点

新增地点已确认是低风险扩展。

需要补：

- `LocationDef`
- `LOCATIONS`
- `mapX / mapY`
- `WALK_EDGES` 或依赖公交/出租车
- 相关活动、商店、事件、NPC 日程

会自动建立：

- 地点索引
- 地点事件索引
- 地点活动索引
- 地点商店索引
- 公交/出租车路线

### P2：内容生产管线

目标：正式内容可以稳定生产，而不是继续散在代码里。

工作：

- 事件/工作继续走审查
- 对话/剧情链审查完善
- 内容 schema 校验
- approved 内容进入构建
- 内容 ID/flag 规范
- 内容纪元发布流程
- 多对象行动的组合场景按“平均分配”编写，规则见
  [未来需求 · 多人剧情](future-requirements.md)

### P3：表现层

- 正式头像/立绘
- 场景背景
- BGM/音效
- 移动端细节
- 可访问性
- 存档槽扩展
