## 1. 当前基线

### 游戏定位

- 《偶像大师 闪耀色彩》同人生活模拟；
- Vite + React + TypeScript；
- 开放时间循环，以日程、训练、工作、事件、关系和金钱为核心；
- **正式设定没有结局**；
- 周付款/事务所维持费/债务暂不设计；
- 工作保持低负担：可接、可参与、可不参与，不设缺席惩罚。

### 已实现

- 日期、时间、体力、压力；
- 偶像属性 Rank + EXP、信任；
- 7 天日程和单日覆盖；
- 工作邀约、自动完成、可选参与；
- 事件触发、条件、效果、选项、事件链；
- 内容审查台：事件/工作新建、编辑、批注、通过、打回、废弃、版本化；
- approved 内容加载和构建校验；
- 商业街礼品店、背包、限购、礼物选择偶像赠送；
- 付费课程、咖啡店午餐；
- 存档 v11；
- 147 个 Vitest 测试、9 条游戏 E2E、1 条审查 E2E。

### 当前内容量

- 约 33 个基础事件 + 已通过事件；
- 3 种基础工作 + 已通过工作；
- 8 个地点；
- 2 个偶像；
- 3 个旧结局定义（已废弃，不接入正式流程）。

### 主要缺口

1. 关系内容没有进入主循环；
2. 没有开放式中期目标；
3. 内容密度不足以长期支撑每日循环；
4. 金钱刚有出口，但还没有经过完整试玩校准；
5. 美术、音频、移动端表现尚未进入正式阶段。

## 2. 设计原则

1. **不为了加系统而加系统**：先验证现有循环，再决定是否扩架构。
2. **低压力的偶像生活**：工作可选，不用缺席惩罚制造负担。
3. **没有结局不等于没有目标**：用关系、职业里程碑、收集和自我目标提供方向。
4. **钱买选择，不买胜利**：金钱用于内容、机会、恢复和关系，不直接买数值最优解。
5. **不新增货币和状态条**：优先使用现有体力、压力、信任、Rank、金钱。
6. **内容优先于系统**：如果加内容能验证方向，就不先造通用系统。
7. **审查流程**：
   - 事件/工作走审查台；
   - 活动和物品目前是静态 TS，属于已接受的手工审查例外；
   - 内容量变大后再考虑扩展 `ReviewKind`。
8. **每个阶段有验收标准**：没有验收标准的内容不进入路线图。

## 3. 优先级总览

| 优先级 | 事项 | 原因 |
|---|---|---|
| P0 | 试玩校准现有经济与日常循环 | 刚加入商店/礼物/课程/餐费，尚未验证 |
| P1 | 关系循环 | 无结局模式下最可持续的长期动机 |
| P2 | 开放式职业目标 | 给玩家中期方向，不依赖结局和周付款 |
| P3 | 内容密度 | 防止两周后重复感过强 |
| P4 | 表现、美术、音频、发布 | 循环成立后再投入 |
| 延后 | 周付款/债务/事务所考核 | 已明确暂不设计 |
| 延后 | 新偶像、装备系统、复杂商店 | 先让现有内容成立 |

## 5. 阶段详情

### 阶段 0：试玩校准

**目标**

不写新系统，先验证当前循环是否值得继续扩展。

**工作**

- 连续玩 7–14 个游戏日；
- 记录每天的行动、金钱、压力、工作、礼物、课程、餐费；
- 观察是否出现“不知道干什么”；
- 观察是否出现“只有一种最优玩法”；
- 调整课程价格、餐费、礼物价格、工作收入和压力变化；
- 记录重复事件。

**验收**

```text
一周至少 2 次有意义的消费决策
钱至少有一次低于 2000
没有“每天固定训练→工作”的唯一解
压力至少触发过一次恢复决策
没有因为价格过高而完全不用某类内容
```

**输出**

- 一份试玩记录；
- 一张数值调整清单；
- 不新增系统。

---

### 阶段 1：关系循环

**目标**

让关系成为玩家安排时间的原因，而不是只显示 Rank。

**工作**

每个偶像先做 3 个信任门槛场景：

```text
信任 E：日常对话
信任 D：共同外出
信任 C：更深入的个人事件
```

同时：

- 礼物送出后的后续反应；
- 1 个可主动安排的外出活动；
- 高信任时提供压力恢复；
- 关系事件解锁新的工作、对话或地点内容；
- 关系内容优先走事件审查流程。

**验收**

```text
玩家会为了某个偶像安排某一天
关系不只是数值，而是能解锁场景
关系能影响压力、工作或日常选择
```

**建议先做**

- 真乃和灯织各 1 个信任 D 场景；
- 1 个共同外出活动；
- 1 个礼物后续事件。

---

### 阶段 2：开放式职业目标

**目标**

在没有结局、没有周付款的前提下，给玩家中期方向。

**工作**

- 工作等级/解锁条件；
- 2–3 种新工作类型；
- 粉丝信/评价；
- 排名里程碑；
- 工作室升级；
- 工作板每周刷新；
- 可选的制作人手账目标。

制作人手账示例：

```text
本周想做的事：
□ 存到 8000
□ 和真乃去一次咖啡店
□ 完成一次电台工作
□ 把表现练到 C
```

完成给内容或小奖励，不完成没有惩罚。

**验收**

```text
玩家打开游戏时知道自己这周想做什么
工作不是随机奖励，而是职业路径
钱能推动职业目标
```

---

### 阶段 3：内容密度

**目标**

降低长时间游玩后的重复感。

**工作**

- 2–3 种新工作；
- 15–20 个新事件；
- 3–5 条事件链；
- 1 个新场景；
- 地点专属事件；
- 同一事件按压力/信任/排名变体；
- 事件链优先于单发事件。

**验收**

```text
连续两周不大量重复同一文本
每个地点有辨识度
玩家能说出至少 3 个记得的事件
```

---

### 阶段 4：表现与发布

**目标**

从“能玩的原型”走向“可以展示的版本”。

**工作**

- Q 版头像/立绘；
- 场景背景；
- BGM/音效；
- 移动端细节；
- 可访问性；
- 存档/性能；
- 审查页扩展到活动/物品（如果内容量需要）；
- 清理废弃的考试/结局代码。

**验收**

```text
新玩家无需 debug 即可完整体验
移动端无横向溢出
没有影响主循环的存档/性能问题
```

## 7. 当前不做

```text
❌ 周付款/债务/事务所考核
❌ 结局/考试接线
❌ 第三个偶像
❌ 新货币或新状态条
❌ 装备/服装系统
❌ 更复杂的商店/库存
❌ 继续增加商品数量
```

这些事情不是永远不做，而是**当前阶段不做**。

## 8. 决策记录

| 日期 | 决策 | 说明 |
|---|---|---|
| 2026-10-26 | 无结局 | 考试/结局是早期废弃内容，不接入正式流程 |
| 2026-10-26 | 周付款暂缓 | 交钱维持事务所的方向保留，但不急着设计 |
| 2026-10-26 | 金钱作为内容钥匙 | 先做礼物、课程、餐费、商店，而不是债务 |
| 2026-10-27 | 礼品店在主栏位 | 侧边栏只保留背包等全局功能 |
| 2026-10-27 | 礼物默认当前偶像 | 可切换赠送对象；赠送不切换当前偶像 |
| 2026-10-27 | 购买/赠送不消耗时间 | 按当前试玩方向执行，后续可重新评估 |
