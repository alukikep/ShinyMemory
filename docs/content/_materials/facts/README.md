# 角色资料（facts，28 人 + 事务所 1 人）

> 从外部整理仓库 `eidolon-sc/characters/facts` **整份复制**进本仓库（2026-11-01），
> 之后**不需要再去那边**：要补资料就在这里改，或按 `.sources.md` 的定位重新导出剧本。
> 51 个文件、约 1.7 MB，纯 Markdown，程序不读。

## 1. 结构

| 文件 | 内容 |
|---|---|
| `<id>.md` | 角色资料正文：档案 / 组合 / 人物关系 / 喜好，按 `#` 标题分节 |
| `<id>.sources.md` | 上面每一节的出处记录（官方站、维基、剧情「目录 / 卡名 / 话名」） |
| `example.md` | 空模板，照它的标题结构写新角色 |

`<id>` 与我们内容包里的 `nickName` 一致（`mano` / `hiori` / `kaho` …），
另有一份 `hazuki`（事务所的はづき，staff，不是偶像）。

## 2. 怎么用（重要）

**它是线索，不是 canon。**

```text
facts（面）→ 找到对应的剧本「目录 / 卡名 / 话名」→ 导出剧本拿到 13 位行 id → 写中文
```

- 写进 `docs/content/<id>/character.md` 的每条事实，出处必须是**剧本行 id**；
  `content:guard` 会拦"事实行没有行 id"。
- facts 的 `sources.md` 只记到**话名**级，不能直接当出处。
- 指不回剧本的（尤其"某某说她…"这类关系描述），要么标「待核」，要么不写。

## 3. 和角色卡的分工

| 文件 | 用途 | 规模 |
|---|---|---|
| `facts/<id>.md` | **资料库**：全，但不带行 id，写之前用来建立印象、找线索 | 1 份 10–40 KB |
| `docs/content/<id>/character.md` | **写作用**：只留真会用到的判断（一句话、语言习惯、语域、OOC、三个判断），每条事实带行 id | 1 份 ~5 KB |

先看 facts，再写 character.md；两者冲突时**以剧本为准**，改 facts。

## 4. 出处与使用范围

`sources.md` 里记了整理的依据（官方站、动画官网、萌百 / pixiv / JA 维基 / gamedbs，
以及剧情原文所在仓库的「目录 / 卡名 / 话名」）。这些是**同人整理**，不是官方文本；
仓库内部开发使用，公开分发前要另行确认。

## 5. 更新

- 要补某个角色的细节：先在 `.sources.md` 找到对应剧情，用
  `npx tsx tools/scriptExport.ts <剧本编号>` 导出（缓存到 `.cache/shiny/`，不提交），
  核对原文后**同时**更新 `<id>.md` 和 `character.md`。
- 加新角色：复制 `example.md` 为 `<id>.md`，按节填；有出处就配 `<id>.sources.md`。
