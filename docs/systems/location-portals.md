# 地点入口（区）方案：评估

> 你的想法：保留原来的地点，但在地图上层加一个"入口"——例如「练习街区」里面再选「练习室 / 录音棚」。
> 结论先行：**这比 M1（合并地点）便宜得多，内容一行都不用改。**

---

## 1. 和 M1 的差别

| | M1 合并地点（已 stash） | 入口层（本方案） |
|---|---|---|
| 原地点 id | 删除、全部重映射 | **全部保留** |
| 内容引用 | 151 处（行动/日程/工作/商店/章节/E2E） | **0 处** |
| 存档 | 必须迁移（schema 19） | **不迁移**（旧档在任何地点都有效） |
| 单元测试 | 78 条断言要按新语义重写 | 只加不删，约 5 条 |
| 地图 | 6 个节点，点进去直接做事 | 6 个入口 + 原来的地点，入口里多一次点击 |
| 风险 | 高（语义耦合） | 中低（只是导航层） |

你判断得对：**这是"加一层入口"，不是"改内容单位"。**

---

## 2. 模型

入口本身也是一条 `LocationDef`，只是多了一个 `members`：

```ts
export type LocationDef = {
  id: string;              // 'studio_district'
  name: string;            // '练习街区'
  description: string;     // 这一带是什么、有什么
  kind: 'place' | 'street' | 'station' | 'area';
  members?: string[];      // ['practice_room', 'studio']（仅 kind='area'）
  mapX?: number;
  mapY?: number;
  reachable?: boolean;
};
```

规则：

- **进入是 0 分钟移动**：`area → member` 与 `member → area` 各一条 0 分钟边，不消耗时间，也不触发事件。
- **presence 不变**：偶像的日程仍然写着 `practice_room` / `studio`，玩家站在入口（`studio_district`）时**看不到里面的人**，必须先进入。
- **地图只画入口与独立地点**：成员不画节点；玩家站在 `practice_room` 时，地图把 `studio_district` 标成"当前"。
- **行动/事件/日程/章节全部照旧**：它们认的仍然是 `practice_room`，引擎不需要改任何判定。
- **交通**：巴士枢纽从 `station` 改到入口 `ekimae`（车站是它的成员）；巴士只发往"入口 + 独立地点"，不会出现"坐巴士去练习室"。

入口页面的动作由场景自动生成：

```text
练习街区
  一栋旧楼，楼下练习室，楼上录音棚。
  [ 进入 练习室 ]  [ 进入 录音棚 ]  [ 离开 ]
```

成员页面多一个 `[ 回到街区 ]`。

## 3. 需要改的地方（按文件）

| 文件 | 改动 |
|---|---|
| `types.ts` | `LocationKind` 加 `'area'`；`LocationDef.members?` |
| `content/locations/` | 新增 3 个入口：`ekimae`（车站+商业街）、`studio_district`（练习室+录音棚）、`seaside`（公园+泳池+医院）；原地点全部保留 |
| `content/map.ts` | 入口之间、入口与独立地点之间的步行边；入口↔成员 0 分钟边 |
| `content/transit.ts` | 枢纽 = `ekimae`；只给入口与独立地点发线路 |
| `scene.ts` | `kind==='area'` 时生成本地入口动作；成员页生成"回到街区" |
| `CityMap.tsx` | 过滤成员节点；当前地点在成员上时高亮它所属的入口 |
| `productionMap.test` | 入口要有坐标和边；成员必须有父入口；独立地点照旧 |
| `tests/prologue` | 加一条"从站前进入商业街"的 E2E；旧的 `jumpTo('practice_room')` 仍然有效 |
| 文档 | 新角色接入：写在哪个入口里；`content:where` 增加"入口 → 成员"检索 |

**不需要**：改任何 approved 内容、改任何日程、迁移存档。

---

## 4. 风险与取舍

| 风险 | 处理 |
|---|---|
| 多点一次才能做事 | 入口页把两个成员并排做成大按钮；"离开"回上一级 |
| 玩家站入口时看不到偶像 | 入口页文案提示"人在里面"；成员页才显示偶像 |
| 地图高亮错位 | 从成员反查父入口（`parentOf`） |
| 巴士路线把房间当站点 | 线路只对入口/独立地点生成 |
| 事件在入口触发？ | 入口不挂任何行动/事件；进入成员才结算 |

---

## 5. 建议

先做 **练习街区 → 海滨**（这两个不涉及交通枢纽），验证"入口 + 进入 + 地图高亮"整条链路；
站前（含车站/巴士枢纽）最后做，因为要动 transit。

名字仍然和 id 解耦：入口的 `name` 随时可改，`id` 稳定；内容引用的是成员 id，不受改名影响。
