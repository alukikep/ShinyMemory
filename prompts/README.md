# Prompts（生成与审核提示词）

这里的提示词是**版本化资产**，不是随手改的草稿。每张卡片都记录它用了哪个版本，方便比较“是模型变好了，还是提示词变好了”。

## 建议文件

| 文件 | 用途 |
|---|---|
| `generate-event-v1.md` | 从 canon + 事实 + 效果预设生成完整事件卡 |
| `critic-event-v1.md` | 预审：检查 OOC、设定冲突、事实不符、重复、机制越界 |
| `revise-event-v1.md` | 根据打回原因 + must_keep/must_change 生成新版本 |
| `generate-text-v1.md` | 只生成文本变体（更安全的降级模式） |

## 规则

1. **不在原文件上改**：新版本另存 `v2`，旧版本保留。
2. **提示词必须包含 schema**：模型只能输出合法字段和枚举值。
3. **机制只能从白名单选**：效果预设、条件模板、地点、角色、活动，不能自由发明。
4. **输出必须是结构化 JSON/YAML**：不接受“先解释再给正文”的自由文本。
5. **每次生成记录**：模型、prompt 版本、温度、批次 ID、耗时。
6. **打回原因回流**：把高频原因写进下一版提示词的“禁止事项”。

## 生成完整事件卡的硬约束

```text
你不能发明：
- 新的角色、地点、活动、flag、专有名词
- 新的效果类型或数值；只能从 EFFECT_PRESETS 里选
- 新的条件表达式；只能从 CONDITION_TEMPLATES 里选

你必须输出：
- 符合 EventCard schema 的 YAML
- facts 与 text 分离
- 每个 outcome 使用 presetId
```

没有这些约束，“完整事件卡”会变成大量不可审核的数值噪音。
