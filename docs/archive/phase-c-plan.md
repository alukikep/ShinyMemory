# Phase C 计划：名册头像与当前偶像卡

## 状态

已完成：侧边栏当前偶像卡、偶像名册、偶像互动页均已接入 Q 版头像。

## 目标

让角色在“非 Hero 页面”也有稳定的视觉存在：

- 侧边栏当前偶像卡加入头像；
- 偶像名册卡加入头像；
- 偶像互动页加入头像；
- 属性条颜色和偶像代表色保持一致；
- 保持当前紧凑布局，不恢复大 Hero。

## 为什么现在做

Phase B 把大 Hero 移入侧边栏后，主页面不再显示立绘。  
当前偶像和名册仍然只有文字和属性条，角色识别度不足。

Phase C 用“小头像”补回角色存在感，同时不占纵向空间。

## 资产

新增头像裁切：

```text
public/assets/idols/mano-avatar.png
public/assets/idols/hiori-avatar.png
```

来源：

```text
mano-portrait.png   513 × 1155
hiori-portrait.png  585 × 1214
```

处理方式：

- 从原透明立绘裁切头部/肩部；
- 保留透明背景；
- 统一为 4:5 比例；
- 输出约 256 × 320；
- 不修改原立绘文件。

裁切原则：

- 头顶保留少量留白；
- 不切到眼睛和下巴；
- 包含肩部，避免头像像证件照；
- 深色头发角色需要保留边缘对比。

如果裁切效果不好，退路是：

- 直接使用完整立绘；
- CSS `object-fit: cover` + `object-position: 50% 12%`；
- 但优先使用单独头像素材。

## 数据结构

`IdolDef` 增加：

```ts
avatar?: string;
```

示例：

```ts
avatar: './assets/idols/mano-avatar.png',
```

`IdolPageView` 增加：

```ts
avatar?: string;
```

`ActorView` 暂不增加头像，因为 NPC 没有可用立绘。

## 组件改动

### 1. StatsPanel 当前偶像卡

当前：

```text
樱木真乃  illumination STARS
歌唱 D / 舞蹈 F / ...
```

改成：

```text
┌────────────────────────┐
│ [头像] 樱木真乃         │
│        illumination    │
│        STARS           │
├────────────────────────┤
│ 歌唱 D 0/60            │
│ 舞蹈 F 0/20            │
│ ...                    │
└────────────────────────┘
```

规格：

- 头像 44 × 55；
- 圆角 8px；
- 边框使用偶像代表色；
- 名字 13px；
- 组合名 9px；
- 当前担当标记可选。

### 2. IdolRoster 名册卡

当前：

```text
[名字]
[组合名]
[简介]
[属性条]
```

改成：

```text
┌──────────────────────────────┐
│ [头像] 樱木真乃       [当前]  │
│        illumination STARS    │
│        简介文字...            │
│                              │
│ 歌唱 / 舞蹈 / 表现 / 信任     │
└──────────────────────────────┘
```

规格：

- 名册面板宽度保持 680px；
- 卡片两列布局不变；
- 卡片内部改为 78px 头像 + 内容；
- 属性条横跨整张卡；
- 当前偶像卡边框/背景使用代表色；
- 移动端单列，头像 64 × 80。

### 3. 偶像互动页

当前偶像页面只有文字卡。

增加：

```text
[头像] 樱木真乃
       illumination STARS
       当前训练 / 当前工作
```

规格：

- 头像 56 × 70；
- 与训练/工作标题同一行；
- 不增加大图。

### 4. 角色代表色

使用现有 `IdolDef.color`：

```ts
mano:  #f1b7c5
hiori: #8fa8d8
```

用于：

- 头像边框；
- 当前偶像卡左侧细线；
- 名册当前卡边框；
- 偶像页头像底色。

不要用代表色染整张卡，避免颜色过重。

## 头像 fallback

如果某个偶像没有 `avatar`：

- 显示首字母/姓氏；
- 使用浅青背景；
- 不显示破图。

```tsx
{def.avatar ? <img ... /> : <span>{def.name.slice(0, 1)}</span>}
```

## 风险

- 原立绘裁切可能切到脸或头发边缘；
- 官方素材的授权问题与 Phase B 相同；
- 名册卡加头像后两列可能拥挤；
- 侧边栏高度继续增加，后续加导航时需要重新排；
- 不同偶像的头像构图可能不一致。

## 建议顺序

1. 先裁切两张头像并目测；
2. 接入 StatsPanel，确认侧边栏不拥挤；
3. 接入 IdolRoster；
4. 最后接偶像页；
5. 再做移动端验收。
